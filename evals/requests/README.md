# 固定单请求问题集

`v1.json` 固定 8 个来自真实对局的决策点、输入散列、来源截点、自动检查及逐题人工复核项。问题集独立于模型配置，用于回归比较。

| 类型 | 题目 |
|---|---|
| 回合流程 | 回合开始先抽牌 |
| 已知卡牌处理 | 顶部两张选一张入手、另一张归底 |
| 异议回应 | 伤害加成与抗性抵消后的回应 |
| 效果对象 | 检索对象的阶段及 HP 限制 |
| 附着 | 物品不能按该场景中的附着卡使用 |
| 进化 | 进化来源、实际对象及出场时点 |
| 区域 | 宝可梦卡牌组不能移到竞技场充当竞技场卡 |
| 失败修正 | 散牌与卡牌组容器、占用槽位及失败后的重试 |

## 校验与运行

从项目根目录执行，校验不请求模型：

```sh
npm run eval:requests:verify
```

所需材料全部随仓库保存在 `fixtures/v1/`：固定请求、真实卡文和卡组状态、本局规则与提示词快照、压缩回放记录、离线控制样本及散列清单。索引中的数据包路径相对 `v1.json`，整个目录可复制到其他位置使用。回放记录使用 Node 内置 Brotli 解压，保留状态和事件历史；卡牌图片不参与运行。

运行时绑定问题集，数据或评分不一致会在请求模型前拒绝：

```sh
npm run eval:requests -- run evals/requests/fixtures/v1 --bank evals/requests/v1.json --matrix path/to/models.json --output path/to/new-results --repeats 1 --tool-choice forced
```

模型在每次运行时通过 `--matrix` 显式提供，问题集不指定模型或比较组合。格式为 `[{"id":"配置标识","configFile":"模型配置.json"}]`，配置文件路径相对矩阵文件。模型配置与凭证沿用本机引用，输出目录必须不存在。单独比较工具提交方式时，保持其他输入不变并使用 `--tool-choice auto`。

## 评分约定

分别记录协议、实际执行、规则正确性和耗时。自动检查只覆盖每题 `oracle` 声明的事实；`state_safety` 检查是否新增指定异常。全局规则正确性和行动完成度按每题 `manualReview` 人工复核，不能把自动检查通过写成整局或完整规则通过。

人工复核覆盖本次实际新增操作与副作用，包括使用和弃置的具体卡牌身份、附着对象、条件、时点及容器。读取历史、提交宣告、提出恢复提议分别记录进度；未执行后缀不计完成，失败前已提交的动作保留核验。合法的不同选牌可以通过，历史错误回答不作标准答案。

跨模型输入使用 `portable-v1` 变换，固定请求与此前记录的输入散列一致。提供方恢复数据、原始响应封装和凭证引用不进入题库。执行起点按修订号及请求开始前的工具回执定位，保留已发生的拒绝，排除未来失败和中止记录。每个候选在独立状态中只执行一次有效前缀。

`controls.json` 包含 8 个自动检查正例和 5 个历史错误反例，只用于离线验证检查器，不是唯一标准答案，也不指定评测模型。下面的测试会把整个问题集复制到临时目录，校验并回放全部 13 个控制样本，不请求模型：

```sh
node --test --test-name-pattern '仓库问题集复制到独立目录' apps/server/test/request-eval.test.ts
```

## 版本维护

v1 已用于开发和回归评测。扩充题目、改变输入或调整评分时新增版本，不覆盖 v1；模型和思考强度在运行时指定。结果须附问题集标识及散列、源码散列、模型配置、工具方式和重复次数，原始运行及回复保留。
